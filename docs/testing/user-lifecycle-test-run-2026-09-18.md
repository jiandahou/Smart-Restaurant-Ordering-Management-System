# Admin Users 账号生命周期与会话失权 — 2026-09-18

> [缺口清单](release-gap-review-2026-09-18.md) 给 Admin Users 留的剩余验收是
> 「**专用账号创建/角色变更/停用启用；旧会话失权**」。本轮全部跑掉。
> 全程只在**一次性专用账号**上操作，跑完删除；未触碰任何 seed 用户。

## 0. 结论

- **22 项检查全部通过**（生命周期 13 + 角色与等级 8 + 自我保护 1）。
- **旧会话失权是本轮核心，结论是有效的**：改角色、停用，都会让**已签发的 token 立刻失效**。
- 未发现缺陷。3 条一度标红的用例经查是我期望了错的状态码或撞上登录限流。

## 1. 旧会话失权（AUDIT-01/02 的实地验证）

这是 09-16 合入的 security stamp 修复第一次被**独立验证**——此前只在改密码场景下见过。

| 用例 | 结果 | 观察 |
|---|---|---|
| **AU-ROLE-02** | PASS | Staff 升 Admin 后，**升级前签发的 token 立刻 401**。旧会话不会带着旧角色继续跑 |
| **AU-ROLE-05** | PASS | Admin 降回 Staff 后，**那张管理员 token 立刻 401**。**权限不会苟活于降级之后**——这是更危险的方向 |
| **AU-LIFE-10** | PASS | 账号被停用后，**它当时持有的 token 立刻 401** |
| AU-LIFE-11 | PASS | 被停用的账号**无法重新登录** |

> 降级那条尤其重要：如果只在升级时刷新 stamp，一个刚被降权的人可以拿着旧 token
> 继续用管理员权限直到过期。实测不会。

## 2. 账号生命周期（13/13）

| 用例 | 结果 | 观察 |
|---|---|---|
| AU-LIFE-01/02 | PASS | Admin 建 Staff 账号 → 200，`emailConfirmed=true`，出现在本店用户列表且角色为 `['Staff']` |
| AU-LIFE-03/04/05 | PASS | 新账号能登录、能进前台（200）、**进不了管理面（403）** |
| AU-LIFE-09/12 | PASS | 停用 → 200，列表显示 `isDisabled=true` |
| AU-LIFE-13 | PASS | 恢复 → 可以重新登录 |
| AU-LIFE-15/16 | PASS | 删除 → 200；列表里没有了，也**再也登不上** |

## 3. 角色等级规则（8/8）

实现的规则是「**只能分配比自己权限更低的角色**」，并且有一层可分配角色白名单。两层各司其职：

| 用例 | 结果 | 观察 |
|---|---|---|
| **AU-RANK-01** | PASS | Admin 给人升 **Admin（同级）→ 403**「只能分配比自己权限低的角色」 |
| **AU-RANK-02a** | PASS | Owner 给人升 **RestaurantOwner（同级）→ 403**，同一条规则 |
| **AU-RANK-02b** | PASS | Owner 给人升 **PlatformOwner → 400**「Role must be RestaurantOwner, Admin, Staff, or Customer.」——PlatformOwner **根本不在白名单**，和乱填角色名一视同仁 |
| AU-ROLE-01 | PASS | Owner 给人升 **Admin（低一级）→ 200**，「该做的人做得成」 |
| AU-ROLE-03/04 | PASS | 新 token 带上 Admin 权限；但 Admin **仍读不了全平台用户列表**（403） |
| AU-ROLE-06 | PASS | 降级后重新登录：前台 200、管理面 403，权限正确回落 |

## 4. 一处值得称赞的自我保护

| 用例 | 结果 | 观察 |
|---|---|---|
| **AU-LIFE-14** | PASS | Admin 停用**自己的账号** → **403「You cannot change the status of your own account.」** |

这挡住的是一个很现实的事故：管理员误停自己，随后**没有人能再登录去恢复**。
`UpdateUser` 里也有对应的一条（改自己走 profile 流程）。

## 5. 三条我自己的误判（不是产品问题）

| 我以为 | 实际 |
|---|---|
| 「Admin 升不了 Admin 是缺陷」 | 是等级规则，设计如此 |
| 「Owner 升 PlatformOwner 应该 403，给了 400 所以 FAIL」 | 400 更准确——PlatformOwner 不是可分配角色，属于参数非法而非权限不足 |
| 「降级后新 token 也 401，说明降级把账号搞坏了」 | 我的 `login()` 撞上**登录限流**返回 None，请求变成匿名。重测：登录 200，前台 200，管理面 403，完全正确 |

> 第七次同类问题，而且是我**自己在 09-16 报告里写过的那个坑**（「登录一次，复用 token」）。
> 说明写进报告不等于不会再犯——脚本里每个断言前都 `login()` 一次这个习惯本身要改。
