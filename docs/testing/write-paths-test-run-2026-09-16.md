## 5. 第一轮的 5 个 FAIL 全是我的错，不是产品的

| 我以为 | 实际 |
|---|---|
| 「恢复接单不生效」 | 我传的是 `isAcceptingOrders`，契约是 **`acceptingOrders`**。未知字段被忽略，bool 默认 `false`——所以我那次「恢复」其实又暂停了一次 |
| 「营业时间还原不了」 | 我传的是 `openingHours` 数组，契约是 **`openingHoursJson` 字符串** |
| 「非法营业时间被接受（三个 200）」 | 同上，服务端**根本没读到我的数据**，那三个 200 是空操作。用正确契约后四种非法输入全部 400 |

**后果是真实的**：这让生产餐厅 A 一度处于不接单状态。发现后我立即中止其余测试，先把生产恢复，确认 `acceptingOrders=true`、时间与快照一致、顾客 join 200，之后才继续。

> 这是今天**第三次**栽在同一类错误上：断言看的信号不等于我以为的含义。
> 前两次是 `/api/order/guest` 用空列表而非状态码表示无权、菜品改价因缺版本号而 400。
> **对写操作尤其危险**——读操作猜错契约只是测不到，写操作猜错契约会改坏生产。
